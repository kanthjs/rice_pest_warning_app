# ทบทวนสูตรคะแนนความเสี่ยงผลผลิต

วันที่: 2026-11-05
สถานะ: ทำแล้ว (ดูข้อ 7)

## 1. สูตรปัจจุบัน (app.R)

- คิดเฉพาะศัตรูข้าวกลุ่ม High (9 ชนิด)
- ใช้เดือน +2 และ +3 นับจากเดือนที่เลือก
- `degree = sum(risk_val) / 24` โดย `risk_val = ค่าดิบ (0–4) × 3`
  - ตัวคูณ ×3 เป็นค่าคงที่ จึงเท่ากับ `degree = ผลรวมค่าดิบ / 8`
- เกณฑ์: `> 4` = สูญเสีย > 50%, `> 2` = ~20%, `> 0` = ~5%, ไม่งั้นปกติ
- จุดตัดและตัวหาร 24 ผู้พัฒนากำหนดเอง ยังไม่ได้เทียบกับข้อมูลผลผลิตจริง

## 2. ผลวิเคราะห์จากข้อมูลจริง

คำนวณครบ 77 จังหวัด × 12 เดือนปลูก = 924 กรณี

| ระดับ | สัดส่วน |
|---|---|
| ปกติ (0) | 3.4% |
| ~5% (0–2] | 47.1% |
| ~20% (2–4] | 44.7% |
| >50% (> 4) | 4.9% (เจอแค่ 16/77 จังหวัด) |

- ค่า degree: median = 2.00, P90 = 3.5, สูงสุด = 5.125 (สูงสุดตามทฤษฎีคือ 9)
- ค่าดิบของกลุ่ม High: 0 = 2864, 1 = 3790, 2 = 1209, 3 = 391, 4 = 62 แถว

## 3. ปัญหาที่พบ

1. **แยกกลุ่มได้ไม่ดี**: 92% ตกอยู่แค่ 2 ระดับกลาง เกษตรกรได้ข้อความแทบเหมือนกันทุกครั้ง
2. **จุดตัดตรงกับ median พอดี (2.00)**: ข้อมูลขยับนิดเดียว ผลก็สลับระหว่าง ~5% กับ ~20%
3. **ใช้ผลรวมทำให้กลบตัวที่ระบาดหนัก**: ถ้าเพลี้ยกระโดดสีน้ำตาลระดับ 4 ทั้ง 2 เดือน แต่ตัวอื่นเป็น 0 จะได้ degree = 1.0 ซึ่งแปลว่า "~5%" ทั้งที่ระบาดตัวเดียวก็ทำให้เสียหายหนักได้
4. **กลุ่ม Moderate ถูกถ่วง ×2 แต่ไม่ถูกนำมาคิดคะแนน**
5. **ป้าย "~20%", ">50%" ดูเหมือนตัวเลขที่วัดมาจริง** ทั้งที่ยังไม่ได้เทียบกับข้อมูลผลผลิต
6. **ใช้ช่วงเดือนเดียวกันกับทุกศัตรูข้าว**: หอยเชอรี่ (เสียหายหนักระยะกล้า) และบั่ว (เสียหายหนักระยะ vegetative) แทบไม่ถูกนับ

## 4. ข้อตัดสินใจ

### 4.1 สมมติฐานการปลูก

- **"เดือนที่เริ่มปลูก" = เดือนที่หว่าน/ตกกล้า** (นาหว่านน้ำตมเป็นวิธีหลักในภาคกลาง)
- **สมมติข้าวไม่ไวแสง อายุ ~120 วัน** (เช่น พันธุ์ กข) ซึ่งตรงกับที่ app ให้เลือกเดือนปลูกได้ทั้ง 12 เดือน
- ระยะเติบโตเทียบกับเดือน:

| เดือน | ช่วงวัน | ระยะ |
|---|---|---|
| +0 | 0–30 | กล้า / เริ่มแตกกอ |
| +1 | 30–60 | แตกกอสูงสุด / เริ่มกำเนิดช่อดอก |
| +2 | 60–90 | กำเนิดช่อดอก / ตั้งท้อง / ออกดอก (ไวต่อผลผลิตที่สุด) |
| +3 | 90–120 | สร้างเมล็ด / สุกแก่ |

- ข้าวไวแสง (ขาวดอกมะลิ 105, กข6) **ยังไม่รองรับใน v1** เพราะออกดอกตามช่วงแสง (ราวปลาย ต.ค.) ไม่ได้ขึ้นกับเดือนปลูก ต้องเพิ่ม input "ประเภทพันธุ์" ภายหลัง
- ควรเขียนบอกสมมติฐานนี้ไว้ใน sidebar ของ app ด้วย

### 4.2 ใช้น้ำหนักตามระยะแยกรายศัตรูข้าว แทนการใช้เดือน +2/+3

เก็บเป็นไฟล์ `data/pest_stage_weights.csv` ให้ผู้เชี่ยวชาญแก้เองได้โดยไม่ต้องแตะโค้ด

ค่าเริ่มต้น (ร่าง ต้องให้ผู้เชี่ยวชาญยืนยัน):

| ศัตรูข้าว | +0 กล้า | +1 แตกกอ | +2 ออกดอก | +3 สุกแก่ | เหตุผลย่อ |
|---|---|---|---|---|---|
| *(default)* | 0.25 | 0.5 | 1.0 | 0.75 | ระยะ vegetative ชดเชยได้ด้วยการแตกกอ |
| เพลี้ยกระโดดสีน้ำตาล | 0.75 | 0.75 | 1.0 | 0.75 | ระยะต้นเป็นพาหะไวรัส ระยะหลังเกิด hopperburn |
| เพลี้ยกระโดดหลังขาว | 0.5 | 0.75 | 1.0 | 0.5 | |
| โรคใบไหม้ | 0.5 | 0.5 | 1.0 | 0.75 | ระยะออกรวงเป็นคอรวงไหม้ หนักสุด |
| หนอนกอ | 0.25 | 0.5 | 1.0 | 0.5 | ระยะต้นได้ยอดเหี่ยว (ชดเชยได้) ระยะหลังได้รวงขาว |
| โรคขอบใบแห้ง | 0.5 | 0.75 | 1.0 | 0.5 | ระยะกล้าเกิดอาการ kresek |
| หนู | 0.5 | 0.5 | 1.0 | 1.0 | ระยะตั้งท้องถึงสุกแก่ หนักสุด |
| หอยเชอรี่ | 1.0 | 0.25 | 0 | 0 | กัดกินต้นกล้า ~30 วันแรก |
| บั่ว | 0.75 | 1.0 | 0.25 | 0 | หน่อกลายเป็นหลอดหัวหอม ไม่ออกรวง |
| แมลงหล่า | 0.25 | 0.75 | 1.0 | 0.5 | |

ศัตรูข้าวกลุ่ม Moderate / Low ใช้แถว default

### 4.3 สูตรใหม่

```
score = Σ_pest Σ_stage ( ค่าดิบ × severity_factor × stage_weight )
        severity_factor: High = 3, Moderate = 2, Low = 1
```

- **คิดทุกศัตรูข้าว** ไม่ใช่แค่กลุ่ม High (กลุ่ม Moderate/Low ได้ weight น้อยกว่าอยู่แล้วผ่าน severity_factor)
- **จุดตัดใช้ percentile** ของ score จากทั้ง 924 กรณี: P25 / P75 / P95
  - คำนวณใน `process_data.R` แล้วเก็บลง RDS
  - หมายเหตุ: นี่เป็นการจัดอันดับ**เทียบกัน**ระหว่างจังหวัด/เดือน ไม่ใช่ความเสี่ยงสัมบูรณ์ (กลุ่มสูงมากจะมี ~5% เสมอตามนิยาม)
- **กฎกันตัวที่ระบาดหนักถูกกลบ**: ถ้ามีศัตรูข้าวกลุ่ม High ตัวใดมีค่าดิบ = 4 (สูงสุด) ในระยะที่ weight ≥ 0.75 ให้เป็นอย่างน้อยระดับ "สูง" (เดิมเสนอ ≥ 3 ดูข้อ 7)

### 4.4 ป้ายผลลัพธ์

เปลี่ยนจาก % ผลผลิตที่สูญเสีย เป็นระดับความเสี่ยง:

| ระดับ | ป้าย | สี |
|---|---|---|
| < P25 | เสี่ยงต่ำ | success |
| P25–P75 | เสี่ยงปานกลาง | info |
| P75–P95 | เสี่ยงสูง | warning |
| ≥ P95 หรือโดนกฎ 4.3 | เสี่ยงสูงมาก | danger |

แสดง % สูญเสียได้อีกครั้งเมื่อมีข้อมูลผลผลิตจริงมาเทียบ (calibrate) แล้ว

## 5. คำถามที่ยังค้าง

- ~~ค่าดิบ 0–4 ใน Excel นิยามอย่างไร~~ **ตอบแล้ว**: เป็นระดับโอกาสที่จะพบและความเสี่ยง (0 = ไม่พบ/ไม่เสี่ยง, 4 = สูงสุด) โดยมีความหมายว่า "ถ้าพบต้อง action"
  - ผลกับสูตร: ค่านี้เป็น ordinal (มีลำดับ แต่ระยะห่างระหว่างระดับไม่จำเป็นต้องเท่ากัน) การนำมาบวก/คูณถือว่าทุกขั้นห่างเท่ากัน ใช้จัดอันดับได้ แต่ไม่ควรตีความเป็นปริมาณ
  - ผลกับ UI: ค่า > 0 = ควรเฝ้าระวังและ action ถ้าพบ ข้อความในการ์ด "ถ้าพบควรรีบดำเนินการ" จึงตรงกับความหมายนี้
- แหล่งที่มาของค่า 0–4 (ใครประเมิน, ใช้ข้อมูลกี่ปี)
- ชื่อไฟล์ `update2029` หมายถึง พ.ศ. 2569 หรือเปล่า
- มีข้อมูลผลผลิตหรือความเสียหายจริงรายจังหวัดสำหรับ calibrate ไหม (เช่น จากกรมการข้าว หรือ สศก.)
- ใครเป็นผู้เชี่ยวชาญที่จะยืนยันตาราง weight ข้อ 4.2

### ปรับเกณฑ์ override จาก ≥ 3 เป็น = 4

ทดลองกับข้อมูลจริง (สัดส่วน ต่ำ / ปานกลาง / สูง / สูงมาก):

| เกณฑ์ override | ต่ำ | ปานกลาง | สูง | สูงมาก |
|---|---|---|---|---|
| raw ≥ 3, weight ≥ 0.75 | 19.5 | 27.6 | 47.8 | 5.1 |
| raw ≥ 3, weight ≥ 1 | 22.2 | 37.6 | 35.2 | 5.1 |
| **raw ≥ 4, weight ≥ 0.75 (ใช้)** | 23.3 | 47.0 | 24.7 | 5.1 |
| raw ≥ 4, weight ≥ 1 | 23.8 | 48.8 | 22.3 | 5.1 |

ที่ ≥ 3 กฎ override ดันเกือบครึ่งให้เป็น "สูง" ซึ่งกลับไปเจอปัญหาแยกกลุ่มไม่ได้แบบเดิม
ที่ = 4 กฎ override ดันขึ้นแค่ ~5% ซึ่งเป็นกรณีที่ตั้งใจจับจริงๆ
